Arrays and the DOM

Arrays: reading them

An array is a list with indexes from 0. length is how many items it has, so the last item is at length - 1.

at(-1) reads from the end: at(-1) is the last item, at(-2) the one before. toString() turns the list into one string with commas. join(" - ") does the same with whatever you put between.

Try it: log the last item two ways: with length - 1 and with at(-1). Then join with " | ".

Lists change: items are added and taken away.

Adding and removing

At the end of the list: push(x) adds x; pop() removes the last item and gives it back.

At the start: unshift(x) adds x; shift() removes the first item and gives it back. Every other item moves up or down one index.

delete list[1] empties a slot but leaves a hole: the length stays the same. Avoid it.

Try it: predict the list after each line, then run. Add queue.unshift("Zara") and run again.

Three more for joining, copying and cutting.

concat, slice and splice

a.concat(b) makes a new array: a, then b. slice(start, end) copies a piece, stopping before end, like with strings. Neither changes the original.

splice(start, count, …new) changes the array: from index start, it removes count items, then puts any new items in their place. splice(1, 1) removes the item at index 1; splice(1, 0, "x") inserts "x" there.

Try it: use splice to replace "c" with "C". Then check that slice left letters alone.

Next: finding things in an array.

Searching arrays

For an exact value: indexOf(x) gives its first index (or −1), lastIndexOf(x) its last, and includes(x) gives true or false.

For a value that passes a test, give the method a small function. It's called once per item and returns true when that item matches: find(n => n > 10) gives the first item over 10. findIndex gives its index instead. findLast and findLastIndex search from the end.

Try it: find the first score below 50. Then find the index of the last score over 80.

Next: putting a list in order.

Sorting

sort() puts items in alphabetical order, changing the array. reverse() flips the order.

For numbers, plain sort() is wrong: it compares them as text, so 100 comes before 25. Give it a compare function instead: sort((a, b) => a - b) sorts smallest first, b - a biggest first. The same works for objects: (a, b) => a.age - b.age.

Math.min(...nums) and Math.max(...nums) give the smallest and biggest. The ... spreads the list out into separate numbers.

Try it: run and compare the two number sorts. Then sort people by age.

Practice: searching and sorting.

How does a - b work?
sort calls it with two items. A negative answer puts a first, positive puts b first, 0 keeps them. For 25 and 100, 25 − 100 is negative, so 25 goes first. () => Math.random() - 0.5 gives a random order: a quick shuffle.

Now the big one: changing the page with JavaScript.

The DOM: the page as a tree

When the browser reads your HTML, it builds a tree of objects, one per element, called the DOM. At the top is document; inside it html, then head and body, and so on, the same way the boxes sit inside each other.

JavaScript can read and change this tree. Every change shows on the page at once.

Try it: add a <p> inside the div, or give the h1 an id. Watch the tree under the page change.

To change an element, first you have to find it.

Finding elements

document.getElementById("title") finds the element with id="title".

document.querySelector(".note") takes any CSS selector and finds the first match. document.querySelectorAll("li") finds all matches, as a list you can loop over with for…of.

Try it: run it. Then use querySelector to log the second paragraph, using its class.

Found it. Now change it.

Changing elements

el.textContent = "…" replaces the text inside. el.innerHTML = "…" replaces the HTML inside, so tags in it become elements.

el.style.color = "red" changes one CSS property. Names with a dash lose it and capitalise the next letter: background-color becomes style.backgroundColor.

el.classList.add("done") adds a class (remove and toggle too). el.setAttribute("src", "x.png") changes an attribute.

Try it: make the heading's background yellow. Then change the picture's width with setAttribute.

So far the changes happen as soon as the page loads. Better: when the visitor does something.

Events

An event is something that happens on the page: a click, a key press, typing in a box. el.addEventListener("click", function) runs the function every time that element is clicked.

Other events: "input" (the text in a box changes), "mouseover", "submit" (a form is sent). A box's typed text is in its value.

Try it: click the button a few times, and type in the box. Then add a second button that sets the count back to 0.

Last piece: making brand-new elements.

Creating elements

document.createElement("li") makes a new, empty element. It isn't on the page yet. Fill it in, then parent.appendChild(el) adds it as the parent's last child. el.remove() takes an element off the page.

Try it: type a task and press Add. Then make each new task disappear when it's clicked: add a click listener to li that calls li.remove().
