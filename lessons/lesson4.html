Layout: Flexbox and Grid

The display property

You've met block elements (a new line, full width) and inline ones (inside a line, only as wide as their words). The display property switches any element between them:

block · inline · inline-block: sits in a line like inline, but takes a width, height and padding like a block · none: hidden, and its space is gone.

Try it: change inline to inline-block and watch the width work. Then try none.

For real layouts there's a much stronger display value: flex.

Flexbox: a row of boxes

Give a box display: flex and it becomes a flex container: the elements directly inside it (its items) line up in a row, side by side, even if they are blocks.

flex-direction sets the line: row (left to right, the default) or column (top to bottom).

Try it: delete display: flex; and see the blocks stack. Put it back, then add flex-direction: column;.

Next: where the items sit along the line, and across it.

Do the items inside the items line up too?
No. Only the direct children of the flex container become flex items. To line up deeper boxes, make their parent a flex container too.

justify-content and align-items

justify-content places the items along the line: at the start, centred, at the end, or with the spare space shared between them.

align-items places them across the line. In a row, that means up and down. stretch (the default) makes them all as tall as the container.

gap puts space between the items.

Try it: press the options. Find the setting that puts all three boxes in the exact middle.

What if there are too many items for one row?

Wrapping and growing

By default, flex items squeeze onto one line. flex-wrap: wrap lets them flow onto new lines instead, like words in a paragraph.

flex: 1 on an item lets it grow to fill the spare space. If two items have flex: 1 and one has flex: 2, the spare space is shared 1 : 1 : 2.

Try it: give the search box flex: 1; so it fills the bar. Then make the window narrow… or add 4 more buttons and see them wrap.

Before building a menu, a way to style links when the mouse is over them.

Pseudo-classes

A pseudo-class picks elements by their state or position. It's written after a colon:

a:hover a link while the mouse is over it · input:focus the box you're typing in · li:first-child the first item · li:last-child the last · li:nth-child(odd) the 1st, 3rd, 5th…

Try it: hover over the links. Then change odd to even.

A close cousin styles a part of an element, or adds to it.

What else goes inside nth-child()?
A number, like nth-child(3) for the third. Or a pattern: nth-child(3n) picks every third one: the 3rd, 6th, 9th…

Pseudo-elements

A pseudo-element styles a part of an element as if it were its own element. It's written after two colons:

p::first-letter the first letter · p::first-line the first line · input::placeholder the hint text in a box · ::before and ::after add content before or after an element, set with content: "…".

Try it: change the content of .tip::before to "⭐ ". Add an ::after rule to .tip too.

Next: picking elements by how they sit inside each other.

Combinators

A combinator joins two selectors to pick elements by where they sit:

nav a (a space): every a anywhere inside a nav.
ul > li: only li directly inside a ul, not deeper.
h2 + p: the one p right after an h2.
h2 ~ p: every p after an h2 with the same parent.

Try it: change h2 + p to h2 ~ p. Then change .menu > li to .menu li.

When two rules disagree about one element, which wins?

Specificity and !important

When rules clash, the more specific selector wins. Count each selector as three numbers: ids – classes (and pseudo-classes, attributes) – elements. Compare from the left.

p scores 0-0-1. .intro scores 0-1-0, so it beats p. #first scores 1-0-0 and beats both. If the scores are equal, the later rule wins. An inline style beats them all.

!important after a value beats everything. Use it rarely: it makes CSS hard to fix later.

Try it: the paragraph is blue because #first scores highest. Delete the id rule: who wins now? Then add !important to the p rule.

Four small properties come up again and again.

Overflow, z-index, opacity, max-width

overflow: what happens when content is too big for its box. visible spills out (the default), hidden cuts it off, auto adds a scroll bar when needed.

z-index: which positioned box is on top when they overlap. Bigger numbers come to the front.

opacity: from 0 (invisible) to 1 (solid). max-width: a box may shrink, but never grow past this width. img { max-width: 100%; } stops pictures from spilling out of their box.

Try it: set overflow: auto; on .small. Then give .b z-index: 2; to bring it to the front.

Flexbox lines things up in one direction. Grid does rows and columns at once.

Grid: rows and columns

display: grid makes a grid container. grid-template-columns sets how many columns there are and how wide each is; the items fill the cells in order, row by row.

The unit fr means "a share of the free space". 1fr 1fr 1fr is three equal columns. 2fr 1fr makes the first column twice as wide as the second. repeat(4, 1fr) is four equal columns.

Try it: change the columns to 2fr 1fr, then to repeat(4, 1fr). Change gap too.

An item can also take up more than one cell.

Grid: spanning cells

grid-column: span 2 makes an item two columns wide. grid-row: span 2 makes it two rows tall. The other items flow around it.

This is how most page layouts work: a header across the top, a sidebar, the main part, a footer across the bottom.

Try it: make the footer span both columns, like the header. Then make the sidebar the wide column with grid-template-columns: 2fr 1fr.

Next, make things move.

Transform and transition

transform moves, turns or resizes an element without touching the layout: scale(1.2) makes it 20% bigger, rotate(10deg) turns it, translateY(-5px) lifts it 5px.

transition makes a change happen smoothly instead of at once. transition: transform 0.3s; means "when transform changes, take 0.3 seconds".

Try it: hover over the button. Change 0.3s to 2s, then scale(1.2) to rotate(15deg).

A transition needs a change, like a hover. An animation runs by itself.

Animation

An animation has two parts. @keyframes names it and says what happens from start (from, or 0%) to end (to, or 100%). Then animation plays it on an element: which one, how long, and how many times.

animation: bounce 1s infinite alternate; plays "bounce" for 1 second, forever, going forwards then backwards.

Try it: change 1s to 0.3s. Add a 50% step to the keyframes that turns the ball gold.

Last: make the page fit any screen, from a phone to a laptop.

Media queries

A media query applies rules only when the screen matches a condition. @media (max-width: 600px) { … } means "only when the screen is 600px wide or less", which is roughly a phone.

The usual pattern: three columns on a laptop, one column on a phone.

Try it: drag the "Screen width" slider below 600px and watch the columns change. Then change 600px to 450px.

Practice: a photo gallery that fits every screen.

What is a container query?
The same idea, but it asks how wide the box is, not the screen: give the box container-type: inline-size;, then write @container (max-width: 400px) { … }. A card can then change its layout wherever it's placed.
