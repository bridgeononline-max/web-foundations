Tables, forms and boxes

Tables: rows and cells

A table shows information in rows and columns, like a timetable or a price list.

<table> wraps the whole table. Each <tr> (table row) is one row, and each <td> (table data) inside it is one cell. The columns come from the cells lining up, row after row.

Try it: add a third row for "Chai", costing ₹20. Copy a whole <tr>…</tr>.

The first row of a table usually names the columns. That row gets its own tag.

What is border="1"?
It draws lines around the cells, so you can see them. It's an old attribute; in Lesson 3 you'll draw borders with CSS instead.

Header cells and a caption

A cell that names a column is a header cell: <th> instead of <td>. Browsers show it bold and centred.

<caption>, just after <table>, gives the whole table a title.

Try it: change the caption. Then turn a <td> in the first row into <th> and back.

Sometimes one cell should stretch across two columns, or two rows.

I've seen <thead> and <tbody>. What are they?
Optional wrappers: <thead> around the header rows, <tbody> around the rest. They look the same, but help screen readers and styling. Small tables can skip them.

Merging cells

colspan="2" makes a cell two columns wide. rowspan="2" makes it two rows tall.

The merged cell takes the space of the cells it covers, so leave those cells out. In the table below, Monday's row has only 2 <td> where the others have 3: the "Holiday" cell fills two columns.

Try it: change colspan="2" to 1 and see the hole. Put it back. Then make "Ravi" cover both rows with rowspan="2" and delete the second "Ravi".

Tables show information. Forms collect it.

Forms and text boxes

A form collects what the visitor types, like a sign-up page. <form> wraps everything in it.

<input type="text"> is a one-line text box. Give it a name: that is the label the typed words are sent under. <label> is the visible name of a box; its for must match the box's id, so clicking the label puts the cursor in the box.

Try it: click the word "Name", type something, then press Send. Read what the form would send.

Not everything is plain text. Inputs come in many types.

Where does the form actually send it?
To the address in the form's action attribute, such as a server that saves sign-ups. Here nothing is sent: the page just shows you what would go.

More kinds of input

Change type and the same <input> becomes a different control: email, password (hides what you type), number, date, checkbox (tick or not) and radio (pick one).

Radio buttons with the same name form one group: picking one un-picks the others. value is what gets sent for the one you pick.

Try it: pick a radio button, then another. Now change one radio's name to size2 and try again.

Two more controls: a drop-down list and a big text box.

Are there more types?
Yes: color, range (a slider), file, tel, url, time and more. Try changing one here.

Drop-downs and big text boxes

<select> makes a drop-down list. Each choice inside it is an <option>.

<textarea> is a text box with many lines, for messages. Unlike <input>, it has a closing tag.

Add required to any field, and the form won't send until it's filled in.

Try it: press Send with the message empty. Then type a message and send again.

<div>: a box for grouping

<div> is an empty box. On its own it changes nothing you can see; it just holds other elements together, so you can style or move them as one piece.

Most page layouts are built from divs inside divs: a box for a card, a box for a menu, a box for the whole page.

Try it: give the second card a background too. Copy the style attribute from the first.

Copying the same style onto every card gets tiring. Names help.

id and class

Two attributes give elements names, so styles (and later, JavaScript) can find them.

id names one element: no two elements on a page may share an id. class names a group: many elements can share one class, and one element can have several, separated by spaces.

<div id="top" class="card big">

Here the div is the only "top", and is in two groups: "card" and "big". The names do nothing yet. The next page uses them.

The style tag can style every member of a group at once.

Can a link jump to an id?
Yes: <a href="#contact"> jumps to the element with id="contact" on the same page. You'll use this for your portfolio's menu.

The <style> tag

Instead of a style attribute on every element, put all the styles in one <style> tag. Each rule says which elements, then how they look:
which { property: value; }

p means every paragraph, .card every element with class "card", and #top the element with id "top".

Try it: add class="card" to the last div. It gets the card look at once.

Did you notice the cards stretch across the page, while some elements don't? That's next.

Inline and block elements

A block element starts on a new line and stretches across the whole width: <div>, <p>, <h1>, <ul>, <table>, <form>.

An inline element sits inside a line of text and is only as wide as its content: <span>, <a>, <b>, <img>, <input>.

<span> is the inline version of <div>: an empty wrapper for a few words.

Try it: the backgrounds show each element's size. Change the <span> tags to <div> and see what happens.

div and span say nothing about what they hold. Some tags do.

Semantic elements

<div> and <span> are non-semantic: the name says nothing about what's inside. Semantic elements do: they behave like a div, but their name tells the browser what the part is.

<header> the top · <nav> the menu · <main> the main content · <section> a part with a heading · <article> a piece that stands alone, like a post · <footer> the bottom.

Try it: click "About" in the menu: it jumps to id="about". Add a <section id="contact"> and a menu link to it.

Pages hold more than text and pictures: video and sound too.

If they look like divs, why bother?
Screen readers can jump straight to the <nav> or <main>, search engines understand your page better, and your own code is easier to read.

Video and audio

<video> and <audio> play a file, named in src like an image. Unlike <img>, they have a closing tag.

Add controls to show the play button and volume. Without it there are no buttons at all.

Try it: play both. Then add loop to the video, next to controls.

One more kind of tag lives in the head, where nobody sees it.

Can a video play by itself?
Yes, with autoplay muted. Browsers only allow autoplay when the sound is off, so visitors aren't startled.

Meta tags

<meta> tags go in the <head>. They show nothing on the page; they give the browser and search engines facts about it. Three that every page should have:

charset="utf-8": the letters can be any language, and emoji.
name="viewport": fit the page to a phone's screen.
name="description": the line search engines show under your title.

Try it: change the title and the description. Watch the search result under the page.
